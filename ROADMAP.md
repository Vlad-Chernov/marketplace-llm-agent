# Marketplace LLM Agent — Implementation Roadmap

> Выполняем последовательно, по одному учебному блоку. Каждый блок заканчивается проверяемым результатом и Git-коммитом.

**Цель:** создать локального модульного LLM-агента для карточек товаров, анализа отзывов и поддержки покупателей.

**Архитектура:** MVP строится как явные Python-конвейеры с небольшими изолированными модулями. После измерения MVP те же интерфейсы используются в полной версии с LangGraph, пакетной обработкой, расширенной безопасностью и Streamlit.

**Стек:** Python 3.11+, uv, Pydantic v2, SQLite, ChromaDB, BM25, бесплатный LLM API, pytest, Ruff, LangGraph и Streamlit.

**Основной источник:** [«Пет-проект: LLM-агенты»](</Users/vlad/Documents/Codex/2026-08-10/new-chat-2/outputs/pet_project_llm_agents.docx>).

Это мастер-план проекта. Перед началом каждого крупного модуля из него создаётся короткий подробный план только текущего блока с полным кодом, точными командами и ожидаемым выводом. Такой порядок не перегружает новичка кодом будущих этапов и позволяет учитывать результаты уже выполненных экспериментов.

## Общие правила

- Один блок: 45–90 минут.
- Пользователь вручную создаёт файлы и вводит код по инструкции.
- Для каждого программного модуля сначала пишется тест, затем реализация.
- После каждого блока запускаются указанные проверки.
- Следующий блок начинается после сообщения пользователя «готово» и проверки результата.
- API-ключи находятся только в `.env`; `.env` не попадает в Git.
- Синтетические данные воспроизводятся фиксированным `seed` и не хранятся в Git.
- `true_attributes` никогда не передаются рабочему агенту.
- Детерминированные правила реализуются кодом; LLM используется только для смысловых задач.
- Метрики поиска считаются отдельно от метрик ответа.
- Сохраняются результаты по каждому примеру, а не только средние значения.
- Промпты хранятся в отдельных версионируемых файлах, а не строками внутри бизнес-логики.
- В результатах eval сохраняются сырые ответы и точная версия модели.
- При нехватке времени уменьшается объём данных, но не удаляются тесты, метрики, `no_answer` и раздел ограничений.
