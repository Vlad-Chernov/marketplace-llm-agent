# Журнал экспериментов

Здесь фиксируются контролируемые эксперименты: гипотеза, методика, результаты и вывод.

## Требования к журналу

- До завершения проекта должно быть не менее 5 контролируемых экспериментов.
- Для каждого эксперимента сохраняются входные данные, конфигурация, метрики и результаты по отдельным примерам.
- Эксперимент должен быть воспроизводимым.

## Эксперименты

## E-001. Валидность структурированного JSON у Groq

**Дата:** 2026-08-17

**Гипотеза:** Groq с моделью `groq/compound-mini` возвращает JSON, валидный по Pydantic-схеме, для простых задач извлечения.

**Методика:** Пять русскоязычных запросов на извлечение объёма RAM. Схема ответа: `{"ram_gb": int}`. Разрешён один повтор при невалидном JSON.

**Результаты:** 5 из 5 ответов валидны; доля валидных ответов — 1.00. Повторы не потребовались.

**Вывод:** Модель подходит для первого baseline структурированного вывода. Результат ограничен простой задачей и будет проверяться на более сложных сценариях.

## E-003. Legacy linear pipeline vs LangGraph content pipeline

**Дата:** 2026-09-05

по сравнению с сохранённой линейной реализацией на одном наборе данных.

**Методика:** 12 фиксированных SKU из manifest, GigaChat-2-Pro,
`max_attempts=3`. Для каждой версии создавался новый клиент на SKU. Полные
технические traces сохранены в JSON; prompts и ответы модели не сохранялись.

**Конфигурация:** manifest SHA-256
`74f70b71096a1047f16b5c84be47e6b2595dae55ec47b8229ba4cbc3d88e1c74`.
Цены в настройках не были заданы, поэтому стоимость `$0.00` означает
«не измерена», а не «запросы были бесплатны».

| Метрика | legacy-linear-v1 | langgraph-v1 |
| --- | ---: | ---: |

**Артефакт:** [content-pipeline-4c07a2b4fca34ec19adf523e47d5b91f.json](evals/runs/content-pipeline-4c07a2b4fca34ec19adf523e47d5b91f.json).

**Вывод:** в одном контрольном прогоне LangGraph восстановил `LAP-0010`,

## E-004. Zero-shot vs few-shot генерация карточек

**Дата:** 2026-09-06

**Гипотеза:** два похожих примера хороших карточек улучшат качество генерации
без снижения доли успешно завершённых карточек.

**Методика:** 12 фиксированных SKU из manifest, GigaChat-2-Pro,
`max_attempts=3`. Для zero-shot примеры не передавались; для few-shot перед
генерацией выбирались до двух примеров той же категории с совпадающими
подтверждёнными характеристиками. На каждый SKU и версию создавался новый
клиент. В JSON сохранены только безопасные технические поля и ID выбранных
примеров.

**Конфигурация:** manifest SHA-256
`74f70b71096a1047f16b5c84be47e6b2595dae55ec47b8229ba4cbc3d88e1c74`;
examples SHA-256
`a5e8e814e7227136080c955aabcbf753961e54f9550f9dab0ba14c8855422255`.
Цены в настройках не были заданы, поэтому стоимость `$0.00` означает
«не измерена», а не «запросы были бесплатны».

| Метрика | zero-shot-v1 | few-shot-v1 |
| --- | ---: | ---: |
| Success rate | 83.3% (10/12) | 66.7% (8/12) |
| Attribute F1 | 0.868 | 0.667 |
| Hallucination rate | 1.75% | 9.52% |
| Violations | 0 | 6 |
| Средняя задержка | 128.6 с | 90.1 с |
| Prompt / completion tokens | 40,828 / 19,091 | 32,560 / 12,847 |
| Cost USD | не измерена | не измерена |
| Failures | 2 provider errors | 1 provider error, 3 manual review |

**Артефакт:** [content-few-shot-a1d8632f322d4a9c90c04a1ab27439db.json](evals/runs/content-few-shot-a1d8632f322d4a9c90c04a1ab27439db.json).

**Вывод:** гипотеза не подтверждена. Few-shot восстановил `LAP-0003`, но
ухудшил `LAP-0002`, `LAP-0009` и `LAP-0010`; success rate и F1 снизились,
а галлюцинаций и нарушений стало больше. Меньшие задержка и число токенов не
считаются преимуществом, потому что они получены вместе с большим числом
незавершённых карточек. Рабочим вариантом остаётся zero-shot; few-shot не
включается в production-конвейер.

## E-005. Кластеризация E5-эмбеддингов vs фиксированная таксономия отзывов

**Дата:** 2026-09-06

**Гипотеза:** локальная кластеризация похожих отзывов сможет выявлять
повторяющиеся дефекты достаточно хорошо, чтобы дополнить классификацию по
фиксированной таксономии.

**Методика:** сгенерированы 200 отзывов при `catalog_seed=7` и
`review_seed=42`; после общей очистки и дедупликации осталось 56 отзывов.
Таксономический путь классифицировал их через GigaChat-2-Pro. Локальный путь
строил E5-эмбеддинги `intfloat/multilingual-e5-small` и детерминированно
объединял отзывы по cosine similarity с заранее заданным порогом `0.82`.
Скрытые эталонные метки использовались только для оценки.

**Конфигурация:** SHA-256 входного набора
`d40ec4218f3dea55315976b5aadab42a4f6e58dadbb86a3d8ca07bc85fe833e9`.

| Метрика | Таксономия | Кластеризация |
| --- | ---: | ---: |
| Recall дефектов | 1.000 | 0.000 |
| Средняя абсолютная ошибка частот | 0.0 | 4.6 |
| Задержка | 1069.9 с | 7.0 с |
| Ошибки провайдера | 0 | — |
| Число кластеров | — | 1 |
| Purity / доля шума | — | 0.500 / 100% |

**Артефакт:** [review-clustering-7cf25050f46b49e89cd838bbad8529fd.json](evals/runs/review-clustering-7cf25050f46b49e89cd838bbad8529fd.json).

**Вывод:** при заранее заданном пороге `0.82` локальный путь объединил все
56 отзывов в один кластер и не обнаружил ни одного дефекта. Он примерно в
152 раза быстрее, но качество недостаточно для рабочего конвейера. Рабочим
вариантом остаётся фиксированная таксономия. Подбор порога на этом же наборе
нельзя считать доказательством: для него потребуется отдельное train/test
разделение и новый контролируемый эксперимент.

## E-006. Слепое парное сравнение legacy и LangGraph карточек

**Дата:** 2026-09-08

**Гипотеза:** человек чаще предпочтёт карточки LangGraph сохранённой линейной
реализации; независимый LLM-судья достаточно согласуется с человеком, чтобы
быть дополнительным показателем.

**Методика:** 50 синтетических зашумлённых ноутбуков с
`catalog_seed=31`, `noise_seed=41` и `max_attempts=3` обработаны версиями
`legacy-linear-v1` и `langgraph-v1` на одинаковой конфигурации GigaChat.
Из 33 SKU, успешно завершённых обеими версиями, в стабильном порядке выбраны
первые 30. Позиции A/B были скрыты и детерминированно переставлены. Человек
выбрал A, B или `tie`; затем те же пары оценил отдельный LLM-судья.

| Метрика | Результат |
| --- | ---: |
| Кандидаты / общие успешные / выбранные пары | 50 / 33 / 30 |
| Ручные победы: LangGraph / legacy / tie | 16 / 9 / 5 |
| Победы LLM-судьи: LangGraph / legacy / tie | 10 / 15 / 5 |
| Точное согласие человека и судьи | 53.3% |
| Cohen's kappa | 0.264 |
| Ошибки LLM-судьи | 0 |
| Сбои legacy | 6 `LLMProviderError`, 4 `manual_review` |
| Сбои LangGraph | 4 `LLMProviderError`, 4 `manual_review` |

**Артефакт:** [content-pairwise-232c4401044d47029c660ae2c7eb8c6d.json](evals/runs/content-pairwise-232c4401044d47029c660ae2c7eb8c6d.json).

**Вывод:** ручная оценка предпочла LangGraph (16 против 9 побед при 5
ничьих). Однако `κ=0.264` ниже установленного порога `0.40`: LLM-судья не
достаточно согласуется с человеком и не используется как самостоятельный
автоматический критерий качества. LangGraph остаётся рабочим конвейером по
ручному сигналу и предыдущим техническим метрикам; для более надёжного
подтверждения потребуется новая независимая ручная выборка.
