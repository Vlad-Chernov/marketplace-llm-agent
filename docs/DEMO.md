# Сценарий демонстрации MVP

## Подготовка

В `.env` должен быть выбран GigaChat:

```ini
LLM_PROVIDER=gigachat
GIGACHAT_AUTHORIZATION_KEY=<твой_ключ>
GIGACHAT_MODEL=GigaChat-2-Pro
```

Подготовь данные и индекс правил:

```bash
UV_CACHE_DIR=/private/tmp/marketplace-agent-uv-cache make data
UV_CACHE_DIR=/private/tmp/marketplace-agent-uv-cache make ingest
```

`make ingest` может показать предупреждение Hugging Face об отсутствии `HF_TOKEN`. Для публичной embedding-модели оно не блокирует запуск.

## 1. Цель проекта

Marketplace LLM Agent автоматизирует три сценария маркетплейса:

1. создаёт карточку ноутбука по шумному описанию поставщика;
2. классифицирует дефект в отзыве;
3. отвечает покупателю по правилам магазина с цитатами.

## 2. Сквозной запуск

Для веб-демонстрации открой два терминала:

```bash
UV_CACHE_DIR=/private/tmp/marketplace-agent-uv-cache make api
```

```bash
UV_CACHE_DIR=/private/tmp/marketplace-agent-uv-cache make ui
```

Открой `http://localhost:8501`. Пока карточка или ответ поддержки
генерируются, можно переключаться между разделами: операция продолжается в
backend, а интерфейс автоматически получает результат по `job_id`.

Для терминального сценария используй:

```bash
UV_CACHE_DIR=/private/tmp/marketplace-agent-uv-cache make demo
```

В терминале появятся три блока:

```text
=== Карточка ===
SKU: ...
Статус: completed
Заголовок: ...

=== Отзыв ===
Дефект: ...
Серьёзность: ...

=== Поддержка ===
Статус: answered
Ответ: ...
Цитаты: ...
```

Что показать:

- карточка создана только из подтверждённых характеристик;
- отзыв размечен фиксированной таксономией дефектов;
- ответ поддержки основан на найденных правилах, а идентификаторы policy-фрагментов указаны в цитатах.

## 3. Безопасность поддержки

Support-агент:

- вызывает `search_policy` для вопросов о правилах;
- вызывает `get_order`, если указан номер заказа;
- не раскрывает email, адрес и телефон покупателя;
- блокирует prompt injection и запросы выполнения кода;
- ограничивает число шагов и повторные вызовы инструментов.

## 5. Ограничения

- Golden-набор маленький, а review recall измеряется на одном кейсе.
- Ответы внешней LLM могут иметь нестабильную задержку.
- Кэш снижает число повторных запросов; поэтому токены и latency разных прогонов нельзя сравнивать напрямую.
- Стоимость не измерена, пока цены модели не указаны в `.env`.
- Demo-задачи хранятся в памяти FastAPI и исчезают при перезапуске backend.

## Частые проблемы

- `HTTP 400` или `401`: проверить ключ и `LLM_PROVIDER` в `.env`.
- Используется не тот провайдер: выполнить `unset LLM_PROVIDER` в текущем терминале.
- Ошибка сертификата GigaChat: повторить шаг установки сертификата из `README.md`.
- `HTTP 429` или сетевой сбой: повторить команду; успешные LLM-ответы уже сохраняются в кэш.
