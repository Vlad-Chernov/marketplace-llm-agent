# Сравнение GigaChat и Groq — дизайн эксперимента

## Цель

Сравнить двух облачных провайдеров на одинаковом golden-наборе MVP и выбрать
рабочий вариант по качеству и надёжности, не смешивая влияние кэша, входных
данных и конфигурации приложения.

## Участники и данные

Сравниваются:

- `gigachat` с моделью из `GIGACHAT_MODEL`;
- `groq` с моделью `groq/compound-mini` из `GROQ_MODEL`.

Обе версии получают все 25 кейсов из `data/gold/mvp_cases.json` в исходном
порядке. Для каждого провайдера и каждого кейса создаётся новый LLM-клиент и
новый `MvpCaseExecutor`. Локальные репозитории, правила, таксономия и индекс
policy общие только как read-only входы. `CachedLLMClient` не используется.

## Запуск

Новый CLI запускает оба пути последовательно: сначала GigaChat, затем Groq.
`LLM_PROGRESS=1` печатает провайдера, номер кейса, тип кейса и результат.
Ошибка одного кейса записывается в результат и не останавливает второй
провайдер или оставшиеся кейсы.

Параметры запуска фиксируются в артефакте:

- ID запуска и время создания;
- путь и SHA-256 golden-набора;
- имена провайдеров и моделей;
- число кейсов;
- отсутствие кэша;
- статус измерения стоимости.

## Метрики

Для каждого провайдера рассчитываются существующие MVP-метрики:

- Attribute F1 и hallucination rate;
- точность validation;
- recall дефектов отзывов;
- accuracy support-инструментов и безопасных отказов;
- число технических ошибок;
- latency p50 и p95;
- prompt и completion tokens.

Стоимость в этом запуске имеет статус `unmeasured`: цены в `.env` равны нулю,
поэтому `$0.00` не трактуется как бесплатный запрос и не участвует в выборе.

## Артефакт и безопасность

Результат сохраняется в `evals/runs/provider-comparison-<run-id>.json`.
Он содержит конфигурацию, агрегированные метрики и безопасные результаты
кейсов: ID, тип, статус, latency, токены и тип ошибки. В артефакт не попадают
API-ключи, prompts, сырые ответы, персональные данные, скрытые эталоны и
содержимое tool traces.

## Решение

Провайдер считается предпочтительным, если у него нет больше технических
ошибок и нет существенного ухудшения quality-метрик; при сопоставимом качестве
предпочтение получает меньший p95 latency. Если один из провайдеров падает на
одном или нескольких обязательных маршрутах либо метрики расходятся, решение
фиксируется как неопределённое и provider остаётся предметом отдельного
разбора.

## Вне scope

- изменение prompts, правил валидации, golden-набора или production-пайплайна;
- включение кэша для ускорения результата;
- сравнение стоимости без заданных цен;
- добавление локальной модели: это отдельный третий эксперимент.
