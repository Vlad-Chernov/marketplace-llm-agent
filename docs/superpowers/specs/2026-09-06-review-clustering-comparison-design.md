# Дизайн эксперимента: кластеризация отзывов и фиксированная таксономия

## Цель

Проверить, может ли локальная кластеризация отзывов по смыслу дополнить или
заменить двухпроходную LLM-классификацию по фиксированной таксономии дефектов.
Эксперимент отвечает на два разных вопроса:

- насколько точно каждый подход группирует известные дефекты;
- способен ли путь без таксономии показать повторяющуюся тему как отдельный
  кластер.

Результат не доказывает обнаружение ранее неизвестного дефекта: текущая
синтетика содержит только пять известных дефектов. Это ограничение будет
записано в журнале экспериментов.

## Набор данных и воспроизводимость

Эксперимент использует 200 синтетических отзывов:

- `generate_clean_products(count=10, seed=7)`;
- `generate_reviews(products, count=200, seed=42)`.

Перед обоими путями текст очищается существующим модулем от PII. Скрытые поля
`defect_label` и `is_delivery_review` не передаются ни LLM-классификатору, ни
кластеризатору. Они используются только после обработки для расчёта метрик.

## Подходы

### Фиксированная таксономия

Существующий `classify_review` получает очищенный текст и YAML-таксономию.
Для каждого отзыва создаётся отдельный LLM-клиентный вызов. Результат —
`ReviewLabels`: ID дефекта, тип обращения, серьёзность и уверенность.

### Локальная кластеризация

Тексты преобразуются локальной `SentenceTransformerEmbedder` с моделью
`intfloat/multilingual-e5-small`. LLM и таксономия в этот путь не входят.

Алгоритм — детерминированная жадная кластеризация с cosine similarity:

1. отзывы сортируются по `review_id`;
2. первый отзыв создаёт кластер;
3. следующий отзыв добавляется в кластер с наибольшим сходством с его
   нормализованным центроидом, если сходство не ниже `0.82`;
4. иначе создаётся новый кластер;
5. после добавления пересчитывается нормализованный центроид;
6. кластеры получают ID `CLUSTER-001`, `CLUSTER-002` в порядке создания.

Порог `0.82` и имя модели записываются в JSON результата. Алгоритм не делает
выводов о названии дефекта: кластер — это сигнал для аналитика, а не готовая
категория продукта.

## Оценка

Для LLM-пути используются существующие метрики: overall recall, recall по
дефекту, средняя абсолютная ошибка частоты и типичные ошибки.

Для кластеров скрытые метки применяются только в evaluator:

- **purity** каждого кластера — доля самой частой скрытой метки;
- **weighted purity** — purity, взвешенная по размеру кластера;
- **defect recall** — доля пяти скрытых дефектов, для которых существует
  кластер с большинством отзывов этого дефекта;
- **mean absolute frequency error** — ошибка частот после сопоставления
  каждого кластера с его большинством;
- **noise share** — доля отзывов в кластерах, где большинство — отсутствие
  дефекта или доставка;
- число кластеров и размер крупнейшего кластера.

Сопоставление с большинством существует только для offline-оценки и не может
попасть в рабочий путь кластеризации.

## Артефакты, безопасность и ошибки

CLI создаёт `evals/runs/review-clustering-<run_id>.json`. В нём хранятся
конфигурация, хэш набора, модель эмбеддингов, агрегированные метрики, ID
отзывов в кластерах и безопасные технические ошибки. Тексты, PII, скрытые
метки, промпты и ответы LLM не сохраняются.

При ошибке LLM конкретный отзыв учитывается как отсутствующая классификация;
при ошибке эмбеддинга весь локальный путь завершается с понятной ошибкой и
без частичного отчёта. CLI показывает прогресс классификации только при
`LLM_PROGRESS=1`.

## Решение

Фиксированная таксономия остаётся рабочим способом отчётности, если её recall
и ошибка частот лучше. Кластеризация может быть принята только как
дополнительный сигнал для поиска тем, если её weighted purity не ниже `0.80`
и она выделяет кластеры известных дефектов без существенного смешивания с
доставкой и отзывами без дефекта.

## Тестирование

Unit-тесты используют заранее заданные двумерные векторы и проверяют
детерминированность, порог, нормализацию центроидов и отсутствие таксономии в
кластерном пути. Отдельные тесты проверяют purity, recall, ошибку частот и
безопасную сериализацию. Интеграционный тест запускает оба пути на маленьком
наборе с `FakeLLMClient`.
